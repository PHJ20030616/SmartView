# Task 6.3 报告页面设计

- 日期：2026-08-17
- 状态：已确认（用户已批准范围与关键决策）
- 关联：Task 6.1 报告表 / Task 6.2 报告生成（`ReportTaskService`）

## 一、背景与目标

报告生成链路（Task 6.2）已完成：会话结束 → `REPORTING` → 报告行(`GENERATING`) + MQ → FastAPI 生成 → `SUCCESS/FAILED`，会话统一 `COMPLETED`。本合同补齐：

1. **后端报告查询接口**（契约已定义但未实现）：`GET /api/interview-sessions/{sessionId}/report`、`GET /api/reports/{reportId}`；
2. **报告失败重试**：新增 `POST /api/reports/{reportId}/retry`；
3. **前端报告页面**：`smartview-web/src/pages/report/ReportPage.tsx` + `features/report/`。

验收标准（来自任务）：
- 面试结束页可进入报告页；
- 报告生成中有明确状态（`GENERATING` 轮询）；
- 报告失败时有重试或稍后再看引导。

## 二、关键决策（已与用户确认）

| 决策 | 结论 |
|---|---|
| 实施范围 | 前后端一起实现（接口 + 页面） |
| 问答数据来源 | **扩展契约**：`InterviewReport` 增加 `answers`（含题目/回答/评估），报告响应一次返回全量 |
| 页面入口 | `?sessionId=` 为主（面试结束页带入），`?reportId=` 直查兜底；无参数保持空态引导；**不做历史列表页** |
| 失败重试 | 新增 `POST /api/reports/{reportId}/retry`，`FAILED` 可主动重新生成 |
| 参考答案展示 | 逐题复盘内折叠容器（点开查看） |
| 生成轮询 | 3s 间隔，最长 3 分钟，超时提示可稍后刷新 |

## 三、契约变更（contracts/web-api/openapi.yaml）

### 3.1 新增 schema

```yaml
ReportCoverage:
  type: object
  properties:
    basicCoverage: { type: number, format: double, description: 基础题覆盖比例(0~1) }
    projectCoverage: { type: number, format: double, description: 项目题覆盖比例(0~1) }
    scenarioCoverage: { type: number, format: double, description: 场景题覆盖比例(0~1) }

ReportSuggestion:          # suggestions 的 item 命名化，避免生成无名内联类
  type: object
  properties:
    topic / reason: string
    resources: string[]

AnswerTradeoff:            # ReferenceAnswer.tradeoffs 的 item 命名化
  type: object
  properties:
    aspect: string
    options: string[]
```

### 3.2 InterviewReport 调整

- `coverage` 由 `type: object` → `$ref: '#/components/schemas/ReportCoverage'`
- `suggestions.items` → `$ref: ReportSuggestion`
- `ReferenceAnswer.tradeoffs.items` → `$ref: AnswerTradeoff`
- 新增字段：
  - `roleDirection?: enum[JAVA_BACKEND, AGENT_DEVELOPMENT]` — 报告对应面试方向（前端展示标签）
  - `answers?: AnswerHistoryItem[]` — 问答历史（题目/用户回答/评估），按提问顺序
- `status` 枚举 `[GENERATING, SUCCESS, FAILED]` 保持不变

### 3.3 新增接口

```
POST /api/reports/{reportId}/retry    # 报告 FAILED 时重新生成
  - FAILED    → 报告置回 GENERATING + 重建报告任务(MQ) → 返回重试后报告
  - GENERATING/SUCCESS → 幂等返回现状（不重复触发）
  - 归属校验：报告属于当前登录用户；报告不存在 → 404
  响应：200 InterviewReportResponse
```

### 3.4 前端代码生成

`cd smartview-web && npm run generate:api`。同时修复当前生成的过期类型：`suggestions` 误为 `string[]`、`ReferenceAnswer` 缺 `tradeoffs`、`coverage` 为空对象。

## 四、后端实现（smartview-server）

### 4.1 生成配置

`pom.xml` 的 `openapi-generator models` 白名单追加：`InterviewReport,ReportCoverage,ReferenceAnswer,ReportSuggestion,AnswerTradeoff`（`AnswerHistoryItem` 已在白名单）。生成 DTO `InterviewReport` 与实体同名，业务侧用 import 别名 + 全限定名（沿用 InterviewSessionService 模式）。

### 4.2 ReportQueryService（新建，只读查询）

- `getReportBySession(userId, sessionId)`：校验会话归属（403）→ 按 sessionId 查报告（无 → 404）→ 组装
- `getReport(userId, reportId)`：校验报告归属（403）→ 无 → 404 → 组装
- `retryReport(userId, reportId)`：校验归属 → 委托 `ReportTaskService.retryReportGeneration` → 返回重试后报告
- 组装逻辑（entity → generated DTO）：
  - JSON 字段反序列化：`strengthsJson/weaknessesJson/riskPointsJson` → string[]；`suggestionsJson` → object[]；`coverageJson` → ReportCoverage
  - `referenceAnswers`：按 `reportId` 查表，与历史按 `questionId` 对应
  - `answers`：与 `InterviewSessionService.loadAnswerHistory` 同源——抽取独立组件 `AnswerHistoryAssembler`（注入 question/answer/evaluation mapper + dtoMapper，暴露 `load(sessionId)`），`InterviewSessionService` 与 `ReportQueryService` 共用，避免复制；question/answer/evaluation 白名单字段
  - `roleDirection`：取自会话实体
  - 枚举值安全转换（`readinessLevel/status/answerType/roleDirection`），未知值缺省而非 500

### 4.3 ReportTaskService.retryReportGeneration（新增，事务）

- 前置校验：报告 `status == FAILED`，否则幂等返回（不置改）；同会话无进行中任务（PENDING/PROCESSING/RETRYING）
- 报告置 `GENERATING` + `generatedAt=null` → `updateById`
- 新建 `AiTask`(REPORT_GENERATE, PENDING) → `insert`
- `schedulePublishAfterCommit` 事务提交后投递 MQ（复用既有事务模板，含 REQUIRES_NEW 防幻影事务）

### 4.4 Controller（新建）

- `ReportController`（`@RequestMapping("/api/reports")`）：`GET /{reportId}`、`POST /{reportId}/retry`
- `SessionReportController`（`@RequestMapping("/api/interview-sessions")`）：`GET /{sessionId}/report`
- 均返回 `ApiResponse<generated.InterviewReport>`，方法内取 `SecurityContextHolder.getCurrentUserId()`

## 五、前端实现（smartview-web）

### 5.1 features/report/（新建）

- `reportApi.ts`：`getReportBySessionApi(sessionId)`、`getReportApi(reportId)`、`retryReportApi(reportId)`，axios 封装（复用 `request.ts` + `extractData` 模式）
- `reportService.ts`：`fetchReportBySession/fetchReport/retryReport`，`toReportError(error, fallback)`，`waitForReport` 轮询（3s 间隔、最长 3 分钟，AbortSignal 支持）
- `reportTypes.ts`：`readinessLevel`（NOT_READY/NEEDS_PRACTICE/READY/WELL_PREPARED）、报告状态、答案类型、方向 → 中文标签与颜色映射
- `index.ts` 汇总导出

### 5.2 ReportPage.tsx（重写）

- 入参：读 `searchParams`，`sessionId` 优先、其次 `reportId`；两者皆无 → 保留现有空态引导
- 状态机：`loading → generating｜success｜failed｜error`
  - `generating`：状态面板「正在生成复盘报告」Spinner，`waitForReport` 轮询；超时后提示「生成时间较长，可稍后刷新查看」并行保留返回
  - `success`：全量展示（见 5.3）
  - `failed`：Alert「报告生成失败」+「重试生成」（`retryReport` 后回到 generating）+「稍后再看/返回」
  - `error`：加载失败提示 + 返回/重试（沿用面试会话页 error 范式）
- 轮询终止条件：`status !== GENERATING`；组件卸载 abort

### 5.3 SUCCESS 展示分区

1. 头部总览卡：综合得分（大号数字 + Progress）、准备度 Tag、岗位匹配度
2. 总体评价（summary）
3. 覆盖情况：三阶段（基础/项目/场景）覆盖条，百分比展示
4. 四象限：优势（success 色）、薄弱点（warning）、风险点（error）、建议（suggestions → topic/title + reason + resources 标签）
5. 逐题复盘：`answers` 与 `referenceAnswers` 按 `questionId` 关联；每题卡片 = 题目(#序号+正文) + 我的回答 + 得分/等级/评估 + 折叠的参考答案（`Collapse`：正文 + 关键要点 + 权衡点）

### 5.4 面试结束页接通（InterviewSessionPage.tsx）

- `ended` 分支：新增「查看报告」主按钮 → `/report?sessionId=${id}`；删掉「报告生成功能将在后续版本开放」占位文案

### 5.5 样式

新增报告页样式入 `src/styles/global.css`（沿用 Card/Progress/Tag/state-panel 既有范式，不做新设计系统）。
