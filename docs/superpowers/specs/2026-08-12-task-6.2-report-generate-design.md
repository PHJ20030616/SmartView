# Task 6.2 报告生成设计文档

> 日期：2026-08-12 · 状态：已评审待批准
> 范围：会话结束后创建 `REPORT_GENERATE` 异步任务 → FastAPI 生成综合报告与每题参考答案 → 回写落库

## 1. 目标与验收

**目标**：面试会话结束（自然结束或用户提前结束）后，异步生成面试复盘报告；为每道已回答问题生成参考答案。

**验收标准**：
1. 会话结束后报告状态进入 `GENERATING`。
2. 任务成功后报告状态为 `SUCCESS`。
3. 每道已回答问题（`interview_question.status=ANSWERED`）都有参考答案。

## 2. 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 结果回流 | 扩展 `report_generate_result.schema.json` 携带完整报告内容，FastAPI 只读 MySQL，Spring 落库（沿用画像分析范式） |
| 会话状态机 | 统一为 `REPORTING → COMPLETED`：两个结束路径都先置 REPORTING，报告任务达终态（成功或失败）后推进 COMPLETED |
| 生成方式 | 混合式：得分/准备度/覆盖度确定性计算 + LLM 生成定性内容与参考答案 |
| 分项评分 | 复用现有字段：`overallScore` + `roleFitScore` + 三阶段覆盖率（basic/project/scenario coverage），不改表 |
| 报告失败会话 | REPORTING→COMPLETED（面试已结束，报告独立置 FAILED，避免会话卡"生成中"） |
| HTTP 端点 | 本期不实现 ai-api `/interview/report`（MQ 为唯一生产链路） |
| Agent 拆分 | 架构声明：报告生成作为独立 Agent；`report_generator` 内评分逻辑独立成 `ReportScorer` 类，后续可平移到独立"得分评测 Agent" |

## 3. 数据流

```
会话结束（自然 FINISH / 用户提前结束）→ 会话置 REPORTING
  → [afterCommit] ReportTaskService.startReportGeneration
      ① 幂等创建 interview_report(GENERATING) + ai_task(PENDING, REPORT_GENERATE/INTERVIEW_SESSION)
      ② 发布 MQ 任务消息（仅 sessionId）
  → FastAPI report_worker 消费
      report_generator：读 MySQL 聚合(session/answered题/回答/评估/画像/分析)
        ├ ReportScorer（确定性）：overallScore / readinessLevel / roleFitScore / coverage
        └ LLM（结构化输出）：summary/strengths/weaknesses/riskPoints/suggestions + 每题 referenceAnswers
      → 发布结果消息（envelope + 完整报告内容）
  → ReportResultConsumer → ReportTaskService.handleResult
      成功：更新 report 内容 + SUCCESS + generatedAt + 批量插 reference_answer + 会话→COMPLETED + ai_task SUCCESS
      失败：report FAILED + errorMessage + 会话→COMPLETED + ai_task FAILED
```

## 4. 契约变更（契约优先）

**`contracts/mq/report_generate_result.schema.json`**（本期唯一契约改动）：
- envelope 字段不变（taskId/traceId/messageType/schemaVersion/retryCount/createdAt/sessionId/success/reportId/errorMessage）
- 新增 `success=true` 时必需的内容字段，结构与 ai-api `ReportResponse` 一致：
  - `overallScore`(int 0-100)、`readinessLevel`(enum)、`roleFitScore`(int 0-100)、`summary`(string)
  - `strengths`/`weaknesses`/`riskPoints`(string 数组)
  - `suggestions`(对象数组 [{topic, reason, resources[]}])
  - `coverage`({basicCoverage, projectCoverage, scenarioCoverage})
  - `referenceAnswers`(数组 [{questionId, answerType, referenceContent, keyPoints[], tradeoffs[]}])
- `reportId` 由 worker 按 `sessionId` 查 `interview_report` 反查（任务消息不携带）

`report_generate_task.schema.json` 维持仅 sessionId；web-api/ai-api 契约已在 Task 6.1 对齐，本期不动。

## 5. Spring Boot 侧

### 5.1 ReportTaskService（`report/service`）
- `startReportGeneration(session)`：幂等（会话已有 GENERATING 报告则跳过）创建 `interview_report`(status=GENERATING) + `ai_task`(PENDING) + 组装 `ReportGenerateMessage`，**afterCommit** 后经 `ReportTaskProducer` 发送（保证 FastAPI 读到的 report 行已提交）。
- `handleResult(msg)`：
  - 成功：按 reportId/sessionId 定位报告，更新内容字段 + `status=SUCCESS` + `generatedAt`；批量插入 `reference_answer`（唯一索引 (report_id, question_id, deleted) 兜底防重）；会话 `REPORTING→COMPLETED`；`ai_task→SUCCESS`。
  - 失败：报告 `status=FAILED` + 记录 errorMessage；会话 `REPORTING→COMPLETED`；`ai_task→FAILED`。
  - 全部写库在同一事务，业务校验失败由消费者转 DLQ。

### 5.2 MQ 组件（`task/mq`）
- `ReportTaskProducer`：沿用 `ResumeTaskProducer` 范式（Exchange `smartview.direct`，routingKey `report.generate.task`，带有限立即重试）。
- `ReportResultConsumer`：沿用 `ResumeResultConsumer` 范式（监听 `smartview.report.generate.result.v1`；`BusinessException`→DLQ，系统异常→重试）。
- `ReportGenerateMessage` / `ReportGenerateResultMessage`：与 mq 契约一致。

### 5.3 RabbitMQConfig
新增队列/路由键/死信常量与 Bean（v1 后缀策略）：
`QUEUE_REPORT_GENERATE` / `ROUTING_KEY_REPORT_GENERATE` / `QUEUE_REPORT_GENERATE_RESULT` / `ROUTING_KEY_REPORT_GENERATE_RESULT` + 对应 DLQ。

### 5.4 会话结束接入点
- `InterviewAnswerTxService.applySessionAdvance` FINISH 分支：置 REPORTING 后 afterCommit 触发 `startReportGeneration`（替换现有"留待 Phase 6"注释）。
- `InterviewSessionService.finishSession`：由置 COMPLETED 改为置 REPORTING（+USER_FINISHED_EARLY），afterCommit 触发报告生成。

## 6. FastAPI 侧

### 6.1 report_generator.py（`services`）
`ReportGenerator` 用 SQLAlchemy 读 MySQL：session、ANSWERED 题目、对应回答与评估、resume_profile、profile_analysis、interview_report（反查 reportId）。内部模块化（为后续 Agent 拆分留边界）：
- **`ReportScorer`**（确定性，独立类）：
  - `overallScore` = 全部评估得分加权均值（近题权重略高）
  - `readinessLevel` = 阈值映射（<40 NOT_READY / <60 NEEDS_PRACTICE / <80 READY / 其余 WELL_PREPARED）
  - `roleFitScore` = PROJECT/SCENARIO 阶段答题得分加权均值（体现岗位相关能力）
  - `coverage` = 由 `stage_coverage_json` 计算三阶段覆盖率（covered_topics / required_topics）
- **`ReportNarrativeGenerator`**（LLM 结构化输出一次调用，schema 校验+修复）：summary / strengths / weaknesses / riskPoints / suggestions。
- **`ReferenceAnswerGenerator`**（LLM 结构化输出一次调用）：每题 referenceContent + keyPoints / tradeoffs；answerType 按题目阶段映射（BASIC→BASIC_KEY_POINTS / PROJECT→PROJECT_STRUCTURE / SCENARIO→SCENARIO_FRAMEWORK）；参考答案规则见 §7。

### 6.2 report_worker.py（`workers`）
复制 `profile_worker.py` 范式：aio_pika、traceId 上下文、可重试 `AppError` 白名单（LLM_REQUEST_FAILED / LLM_INVALID_JSON / LLM_SCHEMA_INVALID）、worker 侧有界重试、结果发布、DLQ。

### 6.3 config.py
新增 `rabbitmq_report_generate_queue` / `rabbitmq_report_generate_routing_key` / `rabbitmq_report_generate_result_routing_key` / `rabbitmq_report_generate_dead_letter_*` 配置。

## 7. 参考答案规则

| 题型阶段 | answerType | 内容要求 |
|---|---|---|
| 基础题 BASIC | BASIC_KEY_POINTS | 关键知识点（要点清单 + 简要展开） |
| 项目题 PROJECT | PROJECT_STRUCTURE | 优秀回答结构（STAR 式组织 + 亮点表达） |
| 场景题 SCENARIO | SCENARIO_FRAMEWORK | 分析框架、取舍、落地方案（含 tradeoffs） |

LLM 输入包含题目正文/主题/期望要点与候选人实际回答/评估（命中/缺失要点），使参考答有针对性。

## 8. 测试

- **Spring 单测**：ReportTaskService（建任务幂等、结果成功/失败处理、参考答案批量插入、会话推进）、ReportResultConsumer（业务异常→DLQ）、ReportTaskProducer。
- **FastAPI 单测**：ReportScorer（各指标公式与边界）、report_generator（LLM mock、答案类型映射、schema 校验失败修复）、report_worker（契约校验、重试、失败回传）。
- **集成测试**：报告状态 GENERATING→SUCCESS/FAILED 全链路；每道 ANSWERED 题落库参考答；唯一索引防重复生成。
